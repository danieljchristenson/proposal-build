## 2. What Went Wrong (Honest Debrief)

The proposal build failed for five specific reasons, in order of impact:

### Failure 1 — Wrong base approach

I started by copying the Pier 39 master pptx and doing find-and-replace. That meant every text box was sized for Pier 39's content and every image placeholder was sized for Pier 39's layout. When I dropped Riverside content in, text overflowed boxes and images got distorted at the wrong dimensions.

**Lesson:** The master is a *style reference*, not a *content source*. Match the look, build fresh content sized for the actual content.

### Failure 2 — Most renderings never made it into the deck

I used 4 renderings out of 25+ available. The proposal should be a visual showcase of the renderings the customer paid for. The Bell Display, Spiral LED Tree, Gift Box Tower, all the Lighted Snowflakes shots, the Pole Banner Artwork, multiple wreath shots, multiple garland shots — none of them appeared. This is the single biggest miss.

**Lesson:** Before slide one, build a rendering-to-slide map. Every rendering gets a home, or a documented reason for not being used.

### Failure 3 — Didn't follow the worksheet line-by-line

The worksheet has the exact quantities, prices, and materials notes for every line item. I wrote loose summary bullets. The Scope and Investment slides should mirror the worksheet — same numbers, same labels, same materials notes — not paraphrase.

**Lesson:** Pull line items directly from the worksheet. Don't reinterpret.

### Failure 4 — No QA per slide

I rendered the deck once, eyeballed 4 slides, and called it done. Slides 3, 5, 6, 8, 9, 11, 13 were never visually checked.

**Lesson:** Every slide gets rendered to image and inspected before moving to the next. No batch QA at the end.

### Failure 5 — Treated "build the proposal" as one step

I read "build it" as "produce a full draft in one pass." Should have read it as "produce slide 1, get sign-off, then slide 2."

**Lesson:** 13-slide builds need 13 checkpoints, not 1.

## 3. Reset Plan — How the Next Session Should Run

### The new working pattern

**One slide at a time. Show. Critique. Fix. Lock. Move on.**

Concretely:
1. I render Slide N as an image.
2. I attach it inline in chat for you to see.
3. You critique (or sign off).
4. I fix.
5. We lock that slide. Move to Slide N+1.

Yes this is slower for the first proposal. It's faster for the second proposal because we'll have a locked formula by then.

### Per-slide kickoff brief (use this template for every slide)

Before building a slide, the next session should produce **and the user should sign off on**:

```
SLIDE [N] — [Slide Title]
PURPOSE: [What this slide is supposed to accomplish — one sentence]
AUDIENCE TAG: [Owner/GM, Marketing, Finance, or combination]
LAYOUT: [Reference page number from master template, or describe layout]
CONTENT:
  - Title:
  - Subtitle:
  - Body / Bullets:
  - Sidebar / Callouts:
  - Footer:
RENDERINGS USED: [exact filenames from the renderings folder]
NON-NEGOTIABLES: [things that MUST be exactly right — pricing, customer name, dates]
SOURCE OF TRUTH: [worksheet row references, RFP page numbers]
```

Once this brief is signed off, I build the slide. No deviation.

## 4. Repeatable SOP — Future Proposals

This is the workflow for any St. Nick's proposal going forward, distilled from this project.

### Phase 1 — Project Kickoff (Day 1)

Capture upfront, in a single intake:

1. **Customer:** company name, decision-maker, contact email, billing address.
2. **Presenter:** name, email — gets cited on cover + signature block.
3. **Project:** site name, year, season dates, term length (single or multi-year).
4. **Critical dates:** signing deadline, fabrication lock (90 days pre go-live), go-live, season end.
5. **Constraints:** prevailing wage / certified payroll, permits, after-hours requirements, power availability, traffic control needs.
6. **RFP / source material:** any conceptual deck, drawings, or written scope from the customer.

→ This becomes the **Project Brief** stored in `04 - Process & Notes/Project Brief.md`.

### Phase 2 — Scope & Pricing (Worksheet)

Build the Scope Worksheet as the single source of truth. Iterate with the user until locked. Includes:

- **Base Scope** — items, qty, unit, unit price, line total, rendering reference, materials/build, internal notes.
- **Optional Enhancements** — same columns.
- **Tier scenarios** — Essential / Enhanced (recommended) / Signature, with substitute-not-add logic.
- **Legend** with all assumptions.
- File location: `03 - Scope & Pricing/[Client] - Scope Worksheet.xlsx`.

**Don't move to the deck until the worksheet is locked.**

### Phase 3 — Rendering Inventory

- All renderings in `02 - Renderings/`, named by decor type.
- Subfolders: `Base Scope/`, `Enhancements/`, `Unused Renderings/`.
- **Build the rendering-to-slide map** (see Section 3) before a single slide is started.

### Phase 4 — Slide-by-Slide Build

13-slide deck following St. Nick's master template structure:

1. Cover · 2. Exec Summary · 3. Our Understanding · 4. Creative Vision · 5–7. Zone Pages · 8. Scope of Work · 9. Case Study · 10. Investment · 11. Terms & Next Steps · 12. Let's Make It Happen · 13. About

For each slide:
1. Produce the per-slide kickoff brief (Section 3 template).
2. User signs off on the brief.
3. Build the slide programmatically (don't copy from another proposal — use brand standards + content from worksheet/renderings).
4. Render to JPG, attach in chat.
5. User reviews, gives changes.
6. Iterate until signed off, then move to the next slide.

### Phase 5 — Final QA & Polish

After all 13 slides are signed off:
- Convert to PDF, view all 13 pages back-to-back for consistency check.
- Verify all sources of truth still match (scope worksheet hasn't been changed since deck was built).
- Run a final tone/voice pass.

### Phase 6 — Supplemental Itemized Pricing

Built as a separate 2-page PDF for the recommended tier (Enhanced). Mirrors the master `StNicks_Supplemental_Itemized_Pricing.pdf` structure but with Riverside (or future client) content.

### Phase 7 — Delivery

- Final pptx + pdf saved to `03 - Scope & Pricing/`.
- Supplemental itemized pricing pdf saved to same location.
- Hand-off note in `04 - Process & Notes/` summarizing what was sent and when.
